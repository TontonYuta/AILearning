\chapter{Sổ Tay Lệnh Hệ Thống, Docker, vLLM \& Linux NetOps}
\label{ch:appendix-cheatsheets}

Khi trực tiếp vận hành cụm máy chủ AI quy mô lớn phục vụ hàng triệu người dùng hoặc xử lý sự cố khẩn cấp trong ca trực đêm (\textit{On-Call Incident Response}), kỹ sư không có thời gian tìm kiếm tài liệu trên mạng. Bạn cần những câu lệnh hệ thống chính xác, súc tích, đã được kiểm chứng thực tế tại các môi trường sản xuất khắt khe nhất.

Phụ lục chuyên khảo này tổng hợp các bộ công cụ dòng lệnh (CLI), cấu hình hạt nhân Linux Kernel, kịch bản chẩn đoán mạng NetOps, các cờ tối ưu hóa vLLM và tài nguyên Kubernetes thiết yếu dành riêng cho Kỹ sư AI cấp cao.

\subsection{Khởi Chạy Container Tránh Lỗi Phân Mảnh \& Tràn /dev/shm}

Lỗi kinh điển khiến PyTorch DataLoader bị sập với tín hiệu \code{SIGBUS} là do kích thước bộ nhớ chia sẻ mặc định của Docker (\file{/dev/shm}) chỉ có 64MB. Cấu hình sản xuất chuẩn mực:

\begin{lstlisting}[language=bash]
# Khoi chay container voi IPC Host, ulimit khong gioi han va mount o dia model
docker run -d \
  --name vllm_production_cluster \
  --runtime nvidia \
  --gpus all \
  --ipc=host \
  --ulimit memlock=-1 \
  --ulimit stack=67108864 \
  -p 8000:8000 \
  -v /mnt/fast_nvme/models:/root/.cache/huggingface \
  -v /var/log/vllm:/var/log/vllm \
  vllm/vllm-openai:latest \
  --model meta-llama/Meta-Llama-3-70B-Instruct \
  --tensor-parallel-size 4 \
  --gpu-memory-utilization 0.92 \
  --max-model-len 8192
\end{lstlisting}

\subsection{Cấu Hình /etc/docker/daemon.json Cho GPU Trực Tiếp}

\subsection{Định Nghĩa Deployment Khai Thác GPU Với NVIDIA Resource Requests}

apiVersion: apps/v1
kind: Deployment
metadata:
  name: vllm-llama3-70b
  namespace: ai-serving
spec:
  replicas: 2
  selector:
    matchLabels:
      app: vllm-llama3-70b
  template:
    metadata:
      labels:
        app: vllm-llama3-70b
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/port: "8000"
        prometheus.io/path: "/metrics"
    spec:
      containers:
      - name: vllm-engine
        image: vllm/vllm-openai:latest
        args:
        - "--model"
        - "meta-llama/Meta-Llama-3-70B-Instruct"
        - "--tensor-parallel-size"
        - "4"
        - "--gpu-memory-utilization"
        - "0.92"
        - "--enable-prefix-caching"
        resources:
          limits:
            nvidia.com/gpu: "4"
            memory: "64Gi"
            cpu: "16"
          requests:
            nvidia.com/gpu: "4"
            memory: "32Gi"
            cpu: "8"
        volumeMounts:

      volumes:

          sizeLimit: 16Gi

\subsection{Cấu Hình KEDA Autoscaling Theo Hàng Đợi vLLM}

Thay vì tự động mở rộng theo CPU/RAM thông thường (vốn luôn bão hòa 100\% khi GPU chạy), kỹ sư AI cấu hình KEDA dựa trên số lượng request đang chờ trong hàng đợi vLLM (\code{vllm_num_requests_waiting}):

\begin{lstlisting}[language=bash]
apiVersion: keda.sh/v1alpha1
kind: ScaledObject
metadata:
  name: vllm-queue-autoscaler
  namespace: ai-serving
spec:
  scaleTargetRef:
    name: vllm-llama3-70b
  minReplicaCount: 2
  maxReplicaCount: 8
  cooldownPeriod: 300
  triggers:
  - type: prometheus
    metadata:
      serverAddress: http://prometheus-k8s.monitoring.svc:9090
      metricName: vllm_num_requests_waiting
      query: sum(vllm:num_requests_waiting{app="vllm-llama3-70b"})
      threshold: "10"
\end{lstlisting}

\section{Tinh Chỉnh Nhân Hệ Điều Hành Linux Cho Tải Cao (Kernel Tuning)}
\label{sec:app-cheat-kernel}

Khi phục vụ hàng chục ngàn kết nối WebSocket hoặc SSE streaming đồng thời, cấu hình mặc định của Linux sẽ gây lỗi \code{Too many open files} hoặc từ chối kết nối. Thêm các cấu hình sau vào \file{/etc/sysctl.conf}:

\begin{lstlisting}[language=bash]
# Tang so luong file descriptor toi da ma he thong co the mo
fs.file-max = 2097152

# Tang kich thuoc hang doi backlog chap nhan ket noi TCP
net.core.somaxconn = 65535
net.ipv4.tcp_max_syn_backlog = 3240000

# Cho phep tai su dung cac socket o trang thai TIME_WAIT
net.ipv4.tcp_tw_reuse = 1

# Tang kich thuoc bo dem doc/ghi cho TCP Socket (Buffer Tuning)
net.core.rmem_max = 16777216
net.core.wmem_max = 16777216
net.ipv4.tcp_rmem = 4096 87380 16777216
net.ipv4.tcp_wmem = 4096 65536 16777216

# Tat tinh nang slow start restart sau khi ket noi roi vao trang thai idle
net.ipv4.tcp_slow_start_after_idle = 0
\end{lstlisting}

Áp dụng cấu hình ngay lập tức mà không cần khởi động lại máy chủ:
\begin{lstlisting}[language=bash]
sudo sysctl -p
\end{lstlisting}

Và cập nhật giới hạn tiến trình trong \file{/etc/security/limits.conf}:
\begin{lstlisting}[language=bash]
* soft nofile 1048576
* hard nofile 1048576
* soft nproc 524288
* hard nproc 524288
\end{lstlisting}

\section{PyTorch Production Cheatsheet: Tối Ưu Tốc Độ \& Bộ Nhớ VRAM}
\label{sec:app-cheat-pytorch}

\begin{lstlisting}[language=python]
import torch

# 1. Kich hoat che do compile toi uu tren kien truc PyTorch 2.0+
# Mode 'max-autotune' su dung Triton de tao ra cac CUDA kernel tot nhat
optimized_model = torch.compile(model, mode="max-autotune")

# 2. Quan ly Mixed Precision voi torch.amp.autocast (BF16 khong lo Underflow)
with torch.amp.autocast(device_type="cuda", dtype=torch.bfloat16):
    outputs = model(inputs)

# 3. Don sach bo nho dem VRAM khi xay ra ngoai le OOM trong try/except
try:
    outputs = model(large_inputs)
except torch.cuda.OutOfMemoryError:
    torch.cuda.empty_cache()
    print("VRAM emptied, fallback to chunked execution.")

# 4. Xuat bao cao phan manh bo nho VRAM de tim nguyen nhan ro ri
print(torch.cuda.memory_summary(device=0, abbreviated=True))

# 5. Su dung CUDA Streams de thuc thi bat dong bo (Async Memory Copy)
s1 = torch.cuda.Stream()
with torch.cuda.stream(s1):
    next_batch_gpu = next_batch_cpu.to("cuda", non_blocking=True)
\end{lstlisting}

\section{Tường Lửa Linux iptables/nftables Bảo Vệ Cụm Máy Chủ AI}
\label{sec:app-cheat-firewall}

\begin{lstlisting}[language=bash]
# 1. Thiet lap chinh sach mac dinh DROP toan bo goi tin toi (Default Deny)
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT

# 2. Cho phep loopback va cac ket noi da thiet lap tu truoc
sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# 3. Gioi han toc do ket noi TCP SYN de chong tan cong DoS vao API Serving (Port 8000)
sudo iptables -A INPUT -p tcp --dport 8000 --syn -m limit --limit 50/s --limit-burst 100 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 8000 --syn -j DROP

# 4. Chan ngay lap tuc mot IP nguon co dau hieu tan cong Prompt Injection
sudo iptables -I INPUT -s 198.51.100.42 -j DROP

# 5. Chi cho phep dai IP noi bo cua mang Private Subnet truy cap vao cong vLLM
sudo iptables -A INPUT -p tcp -s 10.244.0.0/16 --dport 8000 -j ACCEPT
\end{lstlisting}
